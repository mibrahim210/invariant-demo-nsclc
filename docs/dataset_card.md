# Dataset card - Invariant synthetic NSCLC-inspired benchmark

Version 1.0 | 25 September 2026 | Status: specified; not yet generated or measured.

## Purpose and origin
A developer-tool demonstration of patient-level train/test leakage, regression tests and commit-bound reports. ALL patients, studies, identifiers, images and labels are fictional and procedurally generated by demo_repo/data_gen.py. No real patient images, records, personal information, client data, social-media data or public datasets are inputs. NSCLC-inspired describes the fictional application context only.

The target is a simulated binary imaging phenotype. Both classes belong to the fictional cohort; neither is a validated healthy/cancer category. Do not use this benchmark for diagnosis, prognosis, treatment, clinical validation, biological inference or claims of real-world model performance.

## Composition and sample format
- 200 patients, one study each, eight slices each: 1,600 samples.
- Exactly 100 patients per class; the independently shuffled patient label is constant across all eight slices.
- One paired .npy array per slice; shape (2,64,64), C-order float32, finite [0,1] values, loaded with allow_pickle=False.
- Channel 0: CT-like phantom. Channel 1: PET-like phantom. Shared anatomy and lesion coordinates; not a 3D volume, real scan, Hounsfield-unit map or SUV measurement.
- Stable identity-based filenames do not contain class labels. All derived samples retain patient_id.

## Metadata and artifacts
Metadata uses slice_id, patient_id, study_id, slice_index, array_path, label, generator_version. slice_id is unique and becomes the DataFrame index; array_path is relative to the demo repository. Sort rows by patient_id then slice_index. Splits return index labels consumed through .loc.

configs/data_generation.json specifies seed 20260925, independent label seed 20260926, dimensions, generation parameters, model and split settings. data/metadata.csv and data/image_manifest.json are generated and committed at freeze. The manifest is sorted by relative POSIX path and hashes the actual array bytes. data/generation_manifest.json records generation provenance. These generated artifacts are not included in Step 3.

## Generation assumptions and engineered correlations
A patient-specific anatomy template and persistent texture are drawn independently of label. A controlled Gaussian lesion-like signal varies by simulated phenotype. Related slices add modest anatomical variation and independent noise. The CT-like and PET-like channels share coordinates, with fixed intensity rules documented in the JSON and implemented in versioned generator code.

Persistent texture deliberately makes patient memorization possible under row-level splitting. This correlation is engineered to expose an ML evaluation defect; it is not evidence about real NSCLC data. Signal amplitudes are initial design choices and do not guarantee a measurable AUC drop. Exact generator numerical behavior must be documented and frozen before hashing outputs.

## Intended split and evaluation
The demonstration contrasts a deliberately buggy row-level stratified 80/20 split with a corrected 80/20 patient-grouped split. The latter is not label-stratified. Both use the same frozen cohort, image-only model inputs and fixed 5-neighbor distance-weighted model on 128 block-mean features. No augmentation or fitted feature transformation is used.

Primary seed: 0. Sensitivity seeds: 1,2,3,4. Primary metric: ROC AUC after mean aggregation of held-out slice probabilities per patient. Secondary metric: slice ROC AUC. Retain every seed and explicitly report undefined metrics as unavailable. The leaky condition's held-out patients may appear in training; its AUC is contaminated. Different held-out populations limit interpretation of the AUC difference.

## Quality and scope
Generation/loading checks should validate counts, uniqueness, patient-label consistency, array existence, shape, dtype, numerical range and manifest bytes. These checks do not establish realistic imaging physics or clinical validity. Core Invariant checks patient independence; train-only fitting and inference consistency remain not_checked. Grouped splitting does not itself prove either of those requirements.

Keep the ordinary baseline tests free of patient-disjointness assertions. Bob adds tests/test_split_invariants.py after Report A, preserving the intended demonstration sequence.

## Reproducibility and availability
Freeze the configuration, generator commit, dependency lockfile, metadata and image manifest before review. Retain all run results and durable split/provenance artifacts. Regenerate arrays only from the frozen implementation and verify their bytes against the manifest. Do not regenerate, tune or select seeds between Report A and Report B.

Track the small metadata/manifests/configuration in Git; exclude bulk arrays, caches and local MLflow output. .bobignore limits model context and is separate from .gitignore. Authorized local analyzers still read metadata programmatically. The study protocol Markdown and PDF must be committed together.
